# 컨베이어

컨베이어의 물리 이송과 checkpoint 및 컨베이어 카메라 raw 스트림 발행은 GPU PC 1의
Isaac Sim이 소유한다. GPU PC 2는 해당 raw 스트림을 구독해 ROI/tracker, 후보 프레임
수집과 대표 프레임 선택을 수행한다. 개인 PC 1의 영상 기반 수확 인식과 GPU PC 1의
Lula RRT 경로 계획은 컨베이어 품질 검사와 분리되며, RViz는 컨베이어와 수확 상태를
원격 표시하는 용도로만 사용한다.

## 공통 사양

- MVP 모듈 수: 3개
- 모듈 길이: 각 0.5m
- MVP 총 길이: 1.5m
- 2차 개발에서는 푸셔 전용 컨베이어 4를 추가해 총 4개, 2.0m로 확장한다.
- 모듈 사이 간격 목표: 5mm 이하
- 모듈 상면 높이 차 목표: 2mm 이하
- 모듈 중심선 오차 목표: 5mm 이하
- 유효 폭: 0.25~0.30m
- 측면 가이드 안쪽 폭: 0.14~0.16m
- 측면 가이드 높이: 40~60mm
- 롤러/벨트 상면 높이: 40~60mm
- 명령 속도: 0.40m/s
- 검증 범위: 0.10~0.40m/s
- encoder 및 belt-state는 사용하지 않는다.
- 세 모듈은 동일한 0.40m/s로 운전하며 한 실행 중에는 속도를 변경하지 않는다.

모든 사과는 rigid body와 collider를 가지며 컨베이어 및 다른 사과와 충돌한다.

## 컨베이어 1: 투입·안정화

- 형식: 평벨트
- 길이: 0.5m
- 로봇 투입 위치: 시작점에서 0.15~0.20m
- 투입 높이: 벨트 상면 위 30mm 이하
- 목표 투입 오차: 중심선 기준 좌우 ±30mm
- 역할: 낙하 충격 완화, 흔들림 감소, 검사 구간 진입 자세 안정화

## 컨베이어 2: 회전·촬영

- 형식: 롤러형
- 길이: 0.5m
- 실제 이송·촬영 유효 구간: 0.40m
- 진입·이탈 trigger collider 배치
- 위쪽 `conv_rsd455`, 왼쪽 `conv_rsd455_01`, 오른쪽 `conv_rsd455_02` RGB-D
  카메라와 영상 토픽은 상시 활성화
- GPU PC 2가 RGB-D 기반 사과 검출과 `apple_id` tracker를 상시 수행하고 검사 ROI
  진입 시 착색·손상 후보 프레임 수집을 시작한다.
- OpenCV는 depth 기반 러버 반사 제거, contour/bounding box, blur 검사와 모델 mask
  후처리에 사용한다. 착색·손상 최종 mask는 segmentation 모델이 출력한다.
- GPU PC 2가 ROI 이탈 완료 이벤트를 받으면 사과 단위 착색률·손상 통합 절차를
  시작한다.
- 카메라 ROI는 품질검사 프레임 수집의 시작과 종료를 판단한다. 판정은 영상
  좌표의 세로 띠가 아니라 depth 로 역투영한 3D 위치로 한다. 카메라 세 대가
  모두 검사 지점을 조준하므로, 각 카메라의 광학 좌표계에서 그 지점은 광축 위
  조준 거리 앞에 있고, 사과가 그 지점에서 허용 반경 안에 있으면 ROI 안이다.
  기본값은 조준 거리 0.40m, 허용 반경 0.08m 다.
- 세로 띠 판정을 쓰지 않는 이유: 그 축이 카메라마다 다른 물리량을 잰다. 수직
  하방을 보는 `conv_rsd455` 는 사과 진행이 image y 로 나타나 image x 변동폭이
  0.184 에 그치는 반면, 45도로 보는 두 대는 image x 가 진행을 재어 변동폭이
  0.784, 0.723 이었다. 세 대에 같은 띠 조건을 걸면 서로 다른 질문을 AND 로
  묶게 되어, 사과가 검사 지점에 없는데도 세션이 열리고 곧 끊긴다.
- depth 가 유효하지 않은 프레임에서는 세로 띠 판정으로 대체한다.
- trigger collider는 컨베이어 진입·이탈 시각, 점유시간 및 공정 상태 전환을 측정하며 프레임 선택에는 직접 사용하지 않는다.
- ID 유실·변경 시 `RECHECK`
- `apple_id` tracker 는 3D 위치의 연속성으로 동작한다. 세션이 끝난 뒤 추적
  유지 시간 안에, 마지막으로 본 위치에서 추적 반경 안에 사과가 다시 나타나면
  같은 개체로 보고 `apple_id` 를 재사용한다. 기본값은 1.5초, 0.12m 다.
- 이 tracker 가 없으면 세션이 열릴 때마다 새 `apple_id` 가 만들어져, 검출이
  한 번 끊긴 사과가 여러 개로 보고된다. 실측에서 사과 하나가 검사 6건으로
  갈렸다.
- 착색·손상 통합에서는 동일 timestamp의 위·왼쪽·오른쪽 3방향 뷰를 사용한다.
- 각 뷰는 GPU PC 2가 사과 mask가 영상 경계에 닿지 않고, mask의 90% 이상이
  검사 ROI 안에 있으며, 유효 depth 픽셀 비율이 80% 이상이고, Laplacian variance가
  100 이상이어야 한다.
- 90%, 80%와 100은 초기 시험값이며 시험 결과에 따라 조정한다.
- 세 뷰 중 하나라도 누락되거나 유효하지 않으면 GPU PC 2가
  `INSUFFICIENT_VIEWS`, 손상 면적 유효 뷰가 2장 미만이면 `RECHECK`로 처리한다.
- 한 검사는 한 순간이 아니라 통과 구간에 걸친 여러 순간을 담는다. 순간마다
  위·왼쪽·오른쪽 3뷰가 동시에 있어야 하며, 기본 순간 수는 8이다.
- `frame_index`는 `순간 순번 x 3 + 뷰 인덱스`(위쪽 0, 왼쪽 1, 오른쪽 2)이고
  `total_frames`는 실제로 발행한 프레임 수(기본 24)다.
- 순간은 통과 구간에 고르게 벌린다. 연속 프레임을 모으면 자세가 거의 같아
  표면 커버리지가 무너진다.
- 뷰별 모델은 목표 착색 mask, 손상 mask와 confidence를 출력한다.
- 사과 단위 착색률은 모든 프레임의 착색 유효 픽셀 수 합을 유효 표면 픽셀 수
  합으로 나누고, 손상 면적/손상률은 유효 뷰 중 최댓값으로 통합한다.
- 이 합산은 뷰별 비율의 평균이 아니다. 뷰마다 보이는 표면 크기가 다르므로
  비율을 평균하면 작은 뷰가 과대 대표되어 표면 비율의 추정량이 되지 않는다.
- 크기는 품질 등급에 사용하지 않는다.
- 합격 기준은 정상 사과 오검출, 착색률 오차, 손상 mask 성능과 손상 면적 오차를
  독립 test 시나리오로 검증하는 것이며 정확한 허용값은 `TBD`다.
- 롤러 mesh는 우선 시각적으로 회전
- 이송은 collision surface의 surface velocity 사용
- 회전은 마찰계수와 angular damping으로 유도
- 사과 rigid body의 angular velocity를 simulation time으로 적분해 실제 회전량을 진단한다.
- 회전 부족 시에만 검사 롤러에 revolute joint 적용
- 0.40m/s 기준 목표 검사 시간은 1.0초다. 착색률 측정은 롤러 회전을 표면
  표본추출에 사용하므로, 회전량은 판정 조건이 아니라 커버리지의 근거다.
- 커버리지는 속도가 아니라 이동 거리에 달려 있다. 미끄러지지 않고 구르면
  회전량이 거리에 비례하므로, 같은 ROI 구간을 지나면 속도와 무관하게 같은
  회전량을 얻는다. 실측은 이동 1m 당 약 13회전이었다.
- 표면 커버리지 실측(껍질 중 어느 카메라에서 60도 이내로 보인 비율):
  순간 1개 36.2%, 4개 87.0%, 8개 99.6%. 순간 1개일 때 최대 사각은 155.8도다.
- 착색률 재현성 실측: 한 순간만 쓰면 통과 중 0.68~0.99로 흔들리고(표준편차
  0.079) 등급 경계를 넘나든다. 순간 8개를 합치면 오차가 약 2.8%p다.

## 컨베이어 3: 결과 확인·배출

- 형식: 평벨트
- 사과 이동시간을 simulation time으로 측정
- `apple_id`와 품질 결과의 연결 상태를 확인한다.
- 정상 판정 및 `TIMEOUT`, `LATE_RESULT`, `RECHECK`, `UNCLASSIFIED`, 놓친 사과는 라인 끝으로 배출한다.
- MVP에서는 가상 푸셔, 실제 푸셔, prismatic joint 및 상자 분류를 모두 구현하지 않는다.
- 컨베이어 2·3 진입은 trigger collider로 감지한다.

## 컨베이어 4: 푸셔 분류 구간(2차 개발)

- 2차 개발에서 0.5m 평벨트 모듈을 추가한다.
- 푸셔 3개를 모두 컨베이어 4에 배치한다.
- 상세 사양은 `docs/phases/phase_2_pusher.md`에서 관리한다.

## 시간

- ROS wall time이 아닌 Isaac Sim simulation time을 사용한다.
- 일시정지 시 모든 이송 timer도 정지한다.
- 실제 이동시간을 시험으로 측정하고 이론값과 비교한다.
- 품질 결과 deadline은 카메라 ROI 이탈 후 simulation time 0.5초다. deadline까지 결과가 없으면 `TIMEOUT`, 이후 도착하면 `LATE_RESULT`로 기록한다.

```text
최소 투입 시간 간격 = max(
  로봇 수확시간 상위 95%,
  컨베이어 2 점유시간,
  분류 결과 산출시간 + 안전 여유시간
)

최소 중심 간격 = 컨베이어 속도 × 최소 투입 시간 간격
```

## 미확정 사항

surface velocity 환경에서 사용할 마찰계수와 angular damping, 사과 간 충돌·정체·추월 처리 정책, trigger 크기와 debounce 시간은 구현 시험 결과를 근거로 결정한다. 최소 투입 간격 계산에 필요한 수확시간 P95 산출 방법과 안전 여유시간은 실측 데이터가 확보될 때까지 TBD로 둔다.
